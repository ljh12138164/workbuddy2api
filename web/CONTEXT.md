# Web 领域与模块

## 网关请求

一次通过鉴权和模型权限检查的对话请求。三种协议的消息和流转换由 `server/protocols.ts` 处理，HTTP 编排由 `server/gateway.ts` 处理。

`server/gateway-request.ts` 集中管理请求的准入和结算。调用方不保存租约 owner、不更新请求配额，也不直接删除租约。

## 准入

依次检查每 Key 限流、获取 Key 并发槽、选择并租用账号、原子增加请求计数、更新账号使用时间。账号绑定和账号冷却规则保持不变。

原子增加计数成功后，请求占用一次配额；之后凭证准备或上游调用失败仍计数。此前失败的请求不写使用日志，已取得的租约需要释放。

## 结算

记录日志与 Token 用量，并释放本请求拥有的 Key 和账号租约。多个完成或取消路径共用同一个结算 Promise，后来的调用等待已有结算，不重复记账。日志写入失败不阻止尝试更新用量和释放租约。

流读取期间客户端取消时，停止上游读取，以 499 结算；不再向已取消的客户端写事件。

## 后台数据范围

账号、Key、模型、分组、统计是五种可刷新的数据范围。`app/use-console-data.ts` 集中处理数据加载、操作反馈和刷新失败；页面修改操作声明受影响的范围。

- 复制、读文件、导出、发送验证码和成长任务查询不刷新这些范围。
- 账号修改、导入和手机号验证成功刷新账号；Key 修改刷新 Key；模型修改刷新模型；分组修改刷新分组。
- 手动刷新和登录后的初次加载读取全部五种范围。tRPC 可以将多个 procedure 合并为一个 HTTP 请求。
- 修改成功但刷新失败时保留操作结果，单独提示刷新失败。例如新建 Key 的完整值仍需展示，不能因列表刷新失败丢失。

退出登录或修改密码后清除数据。旧会话尚未完成的刷新结果不能恢复已清除的数据。

## 现有 adapter

数据库使用 Drizzle 的 D1 原生绑定或 D1 HTTP adapter；测试使用 Node SQLite。上游传输使用 fetch，浏览器管理调用使用 tRPC。本次改进没有新增数据库或缓存框架。
